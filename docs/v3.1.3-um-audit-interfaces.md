# v3.1.3 上下游接口设计:UM 号互联网访问审计链 + 标签树删除影响预览

> 2026-10-27,基于 v3.1.2(backport/v3.1-bocha-doubao @ 145ba1216)。零数据库迁移。

## 一、总体链路(UM 号审计)

```
用户(Java 门户)
  │ ①登录态携带 UM
  ▼
Java 门户后端
  │ ②每个 WeKnora 调用带 X-API-Key + X-Tenant-ID + X-External-User-Token(sub=UM 号)
  ▼
WeKnora v3.1.3(:8080)
  │ ③auth 中间件解析出 Principal{Type: APIExternalUser, ID: "<tenant>:<UM>"}
  │   → 写入请求 context(既有机制,零改动)
  │ ④聊天/搜索触发 web_search → WebSearchService.Search(ctx) → DoubaoProvider.Search(ctx)
  │   → RequestActorFromContext(ctx) 取 UM(小写化) → 头 X-External-User-ID
  ▼
DMZ 豆包网关(/apihub/proxy/doubao/search)
  │ ⑤新增:记录 X-External-User-ID + Query + 调用方来源 → 统一互联网访问审计
  ▼
火山豆包搜索(feedcoopapi)
```

## 二、上游契约:Java → WeKnora(零变更,约定固化)

UM 号**不需要任何新字段**——它已经搭在既有的外部用户通道上,本设计只是把约定写死:

| 通道 | 报文 | UM 所在位置 |
|---|---|---|
| **signed_token(推荐,生产形态)** | `X-API-Key` + `X-Tenant-ID` + `X-External-User-Token` | JWT 的 `sub` 声明 = UM 号 |
| direct_header(简化形态) | `X-API-Key` + `X-Tenant-ID` + `X-External-User-ID` | 头值 = UM 号 |

**对 Java 端的要求(既有序,重申):**
1. UM 号格式:4~20 位字符串(全名拼音+数字编号);WeKnora 侧上限 128 字符,超长截断不拒收(审计不阻塞业务)
2. **每个会话期请求都必须重带**外部用户凭证——WeKnora 的会话/检索/搜索均按请求归属用户,缓存 JWT 复用即可
3. 服务级调用(无终端用户的后台任务)不带外部用户头 → WeKnora 不下发 `X-External-User-ID`,DMZ 记录为应用级访问
4. 严禁把 UM 放进 query 文本(会污染检索与改写)

**WeKnora 侧解析规则(v3.1.3 新增代码,行为约定):**
- `Principal{APIExternalUser}` → 取 ID 冒号后的原样外部用户号(即 UM)
- 原生 Web 登录用户 → 用户名
- `Principal{APITenant / Platform / IM / Embed}` → 空(无终端用户,不发头)

## 三、下游契约:WeKnora → DMZ 豆包网关(本版本新增)

**端点不变**(任选其一,由 `web_search_providers.extra_config.endpoint` 配置):

| 环境 | URL |
|---|---|
| 测试 DMZ | `http://30.185.32.29/apihub/proxy/doubao/search` |
| 生产 DMZ | `http://30.17.20.44/apihub/proxy/doubao/search` |
| 外网中转(生产 9100/测试 5100) | `http://42.121.162.30:9100/apihub/proxy/doubao/search` |
| 直连火山(兜底,带 Bearer) | `https://open.feedcoopapi.com/search_api/web_search` |

**新增请求头(唯一变更,向后兼容):**

```http
POST /apihub/proxy/doubao/search HTTP/1.1
Content-Type: application/json
X-External-User-ID: chenfei772         ← 新增:终端用户 UM 号(英文字母小写)
```

- 请求体**完全不变**(Query/SearchType/Count/TimeRange/Filter/ContentFormats/QueryControl)
- 头**始终设置**(DMZ 契约):无终端用户时固定传 `"weknora"`
- UM 号英文字母**必须小写**(DMZ 网关约定)
- **对 DMZ 侧的要求**:网关在访问日志中记录 `X-External-User-ID` + `Query` + 时间戳 + 来源应用;建议同时回显审计回执字段(可选,见下)

**可选增强(二期,需 DMZ 配合):** 响应体增加 `"Audit": {"user_id": "...", "record_id": "..."}` 回执,WeKnora 记入日志,供事后对账。本期不依赖。

## 四、验证方式

1. **单测**:`internal/infrastructure/web_search/actor_test.go` — 外部主体(大写入→小写出)、服务主体→weknora 兜底、原生用户→用户名(小写化),三路断言
2. **联调**:Java 端以某 UM 发起一次带联网搜索的问答 → WeKnora 日志 `[WebSearch][Doubao] ... actor="zhangsan01"` → DMZ 侧查审计记录含同一 UM
3. **回归**:不带外部凭证的既有调用(管理台、后台任务)行为不变(无 X-External-User-ID 头)

## 五、特性 1:标签树删除影响预览(接口)

```
GET /api/v1/knowledge-bases/{kb_id}/tag-tree/nodes/{node_id}/impact
权限:Viewer + KBAccessRead(只读)
→ {"success":true,"data":{"nodes":3,"tags":2,"documents":5,"chunks":12,"affected_tag_ids":[...]}}
```

- `documents` = 将被解除标签的**文档数**(DISTINCT knowledge 条目,含 FAQ 条目)
- `chunks` = 将被清空 tag_id 的分块数
- **零写入**:与 DELETE 的级联统计同源同口径,确认框先调本接口再弹窗;预览失败时退回通用警告文案,不阻塞删除流程
- 前端确认框新增文案(v3.1.3):"本次删除将移除 {documents} 篇文档上的对应标签(涉及 {chunks} 个内容分块)"(zh/en/ko/ru 四语言)
