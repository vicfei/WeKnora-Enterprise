# 二开深水区：四主题路线图（2026-09-10 启动）

评估底座见 `evals/`（标准嵌套题集 eval-100/200/500、共享池模式、
EM/F1/金标命中/top-k 排序指标、配对协议与噪声带）。**每个特性一律
feature 分支 + 请求级开关 + eval-100 池模式 on/off 配对；差异 <2 分
视为噪声不决策；迁移一律 expand-contract 两阶段保证可撤销。**

## 主题 1：知识库路由（feature/kb-routing，进行中）

- **v1.1 已实现**：请求 `enable_kb_routing:true` 且未显式选库时，按
  "问题向量 vs 各库文档向量最大相似度"（max-doc 探针）选 top-3 库；
  决策经 SSE `kb_router` tool_call 事件外发（评估端与前端可消费）。
  单测 + 三题冒烟金标库全中 top-1。
- v1 教训已记录：质心均值被干扰段落稀释 → 错路由；max-doc 修复。
- **eval-100 实测（2026-09-10）**：路由 top1 命中 96% / top3 97%（540 候选库）；
  下游答案 vs oracle 配对 EM +1.0 / F1 -1.3（噪声带内持平）——路由近似无损。
- **待办**：
  生产化前置 = 候选库按用户可见性过滤（v1 是租户全量，见 kb_router.go 警告）；
  大库场景质心/抽样的规模化方案。
- 后续增强：多簇库表示、路由置信度阈值回退（不路由优于错路由）、
  与 agent 工作区范围联动。

## 主题 2：问题/意图/改写资管领域化

- 挂点：`chat_pipeline/query_understand.go`（RewritePromptSystem/User
  已支持 agent 级覆盖）+ `config/prompt_templates`。
- 方案方向：租户级"领域改写词表/风格指引"注入改写提示词；资管术语
  归一（基金代码/公司简称/指标口径）；意图分类增加资管专属意图
  （净值查询/持仓分析/合规问答）。
- 评估：HotpotQA 测不出领域收益——用自建中文资管题集（从真实文档
  出题，几十题即可）+ 池模式 EM/F1 配对。

## 主题 3：多维度综合排序加权

- 挂点：`chat_pipeline/filter_top_k.go` + `rerank.go`（rerank 分、
  向量分、关键词分已在管线内汇合）。
- 方案方向：可配置加权融合（rerank/vector/keyword/recency/文档热度），
  租户级权重配置；先加日志观察各信号分布再定默认权重。
- 评估：**共享池模式的主战场**（top3/5/10 有真实梯度），
  eval-100 配对 + 池模式 top-k 曲线对比。

## 主题 4：文档版本管理

- 现状：`wiki_page_revisions` 已有版本表先例；普通文档无版本。
- 方案方向：文档级 `version` + 更新走"新版本行 + 旧版标记"而非覆盖
  （chunks 绑定版本，检索默认只索引 current）；diff 视图与回滚 API。
- **迁移纪律**：expand-contract——先加可空列双写，读旧写新，稳定后
  再清旧列；回滚 = 代码回退即可，schema 不破坏。
- 评估：功能测试为主（版本正确性/检索隔离），准确率配对确认
  "旧版本不被检索"不伤金标命中。

## 顺序建议与依赖

路由（1）是其余三个的地基：改写（2）改变路由与检索的输入质量，
排序（3）作用在路由选出的候选集上，版本管理（4）改变候选集构成。
1 → 3 并行推进（都有现成评估尺），2 需自建题集先行，4 独立可并行。
