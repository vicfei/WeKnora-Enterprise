5现场实跑：UUM 身份桥接（汇报压轴）

  • 演示故事（两次调用讲完接入）：先登记部门映射（UUM 部门 ID ↔ 预建的 WeKnora 部门租户，1:1 绑定），再 bridge 建号换票——虚构员工 DEMO9001 从"查无此人"到"入部+发 token"一气呵成
  • Header 两个：X-API-Key: $PKEY（platform key，演示者私下保存）＋ X-Tenant-ID: 10003（platform key 门禁要求；端点逻辑以 body 为准）
  • 注意：Swagger UI 的 try-it-out 无法附加自定义 header（端点注解只声明了 body 参数）——Swagger 用于讲解契约，实跑走下面的 curl
# ① 开场：查无此人（期待 404 —— 戏剧性对比）
curl -s -o /dev/null -w "%{http_code}\n" \
  "http://{H}:8080/api/v1/identity/mapping/DEMO9001?tenant_id=10003" \
  -H "X-API-Key: $PKEY" -H "X-Tenant-ID: 10003"

# ② 第 0 步：登记部门映射（DEPT-DEMO 绑定到预建的"汇报演示部"租户 10003，1:1）
curl -s -X PUT http://{H}:8080/api/v1/identity/departments/DEPT-DEMO \
  -H "X-API-Key: $PKEY" -H "X-Tenant-ID: 10003" -H "Content-Type: application/json" \
  -d '{"tenant_id":10003,"department_name":"汇报演示部"}' | jq .

# ③ 压轴：bridge 建号换票（期待 is_new_user:true / 部门:"汇报演示部" / role:"viewer"）
curl -s -X POST http://{H}:8080/api/v1/identity/bridge \
  -H "X-API-Key: $PKEY" -H "X-Tenant-ID: 10003" -H "Content-Type: application/json" \
  -d '{"uum_user_id":"DEMO9001","tenant_id":10003,"username":"演示员工","uum_department_id":"DEPT-DEMO"}' \
  | jq '{is_new_user: .data.is_new_user, 用户: .data.user.username, 部门: .data.active_tenant.name, 角色: .data.memberships[0].role, 已发token: (.data.token|length>100)}'

# ④ 收尾对比：查有此人（期待 200 + user_id）
curl -s "http://{H}:8080/api/v1/identity/mapping/DEMO9001?tenant_id=10003" \
  -H "X-API-Key: $PKEY" -H "X-Tenant-ID: 10003" | jq .data
